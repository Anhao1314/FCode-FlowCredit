# Codex-aligned Agent Console / 本机 Agent 工作台

产品理念与证据边界：`flowcredit/docs/philosophy.md`。

FCode 的视觉基准是 Codex 式任务工作台：大输入框、近黑主行动、紧凑线程、轻量工具卡、
低干扰中性色和即时反馈。这里借鉴的是信息层级与交互节奏，不复制品牌资产，也不引入营销页
渐变。FCode 仍保持中文、本机运行、主机门控、操作员判断、签名链和证据边界。

在线样式页：`flowcredit/viewer/design.html`。
Agent 面向的架构与交互约束：`.agents/skills/fcode-design/SKILL.md`。

## 管辖范围

- **统一覆盖**：Work、Chat、Governance、审计库、设置、右侧详情栏、模型菜单和命令面板。
- **保持不变**：hash 路由、`data-*` 契约、离线 mock、隔离配置、API、运行终态与证据链语义。
- **不再分流**：外壳与证据面不是两套皮肤；证据密集页只提高信息密度，不改变组件语言。
- 最后核对：2026-11-21。

## 六条原则

1. **任务先于装饰。** 首页只突出任务入口、composer 和少量具体建议。
2. **线程先于卡片。** 对话与执行过程按时间阅读；工具、计划和审批只在需要时形成轻量容器。
3. **中性色承担层级。** 黑白灰区分表面、文字和选中态；彩色只表达成功、等待和错误。
4. **主行动明确。** 发送、允许和主要提交使用近黑实心；拒绝是危险操作，不与主行动同样抢眼。
5. **证据不被美化。** 状态标签只翻译服务端事实；失败、停止、待审批和未验证不得包装成完成。
6. **反馈必须诚实。** 停止请求成功只表示请求已发送，最终状态仍由运行流确认。

## 类型层级

- **首页任务标题 32–42px**：最多两行，不使用手写体或营销渐变。
- **页面标题 24px**：治理、审计和设置共用。
- **正文 14–16px**：对话回答优先 16px，密集治理面优先 13–14px。
- **控件 12–13px**：明确、紧凑，不把全部文字都缩成元信息。
- **元信息 10–12px**：等宽用于事件、哈希、命令和数字，不用于长段正文。

## 核心组件

### Composer

- 首页与运行页共用同一组件；首页以任务为中心，运行页固定在底部。
- 18px 圆角、细边、轻阴影；聚焦只增强边界与焦点环。
- 发送按钮为近黑圆形；禁用态仍保持可读，不降低整组控件透明度。
- 审批档位、Fast、模型与附件保持现有数据和行为契约。

### 线程与工具卡

- 用户消息是轻灰气泡；Agent 回答不使用重卡片。
- 工具卡直接显示名称、参数摘要和真实状态；参数、结果与哈希放在展开区。
- 状态至少覆盖：运行中、完成、失败、等待审批、已取消；未知状态显示“状态未知”。
- 长 diff、命令和原始回执允许横向滚动，不撑破文档。

### 审批

- 审批是线程中的决策点，不另开与任务无关的营销式页面。
- “允许”是近黑主按钮；“允许并不再询问”是次按钮；“拒绝”使用危险色文字。
- 操作 preview、影响对象、路径和 diff 直接可见，不用颜色替代文字判断。

### Governance 与审计库

- 与 Work 共用侧栏、按钮、输入框、卡片、状态色和焦点规则。
- 审计库保持高密度表格与长标识符换行；不能为了留白牺牲证据上下文。
- “已验证／已复算”必须有 Runtime 或链验证依据；候选发现不得显示成通过。

### 设置与浮层

- 设置页居中，内部使用左侧章节导航和右侧内容，不引入另一套视觉语言。
- 命令面板采用 combobox/listbox 关系；当前项同时更新 `aria-selected` 与
  `aria-activedescendant`。
- 模态浮层打开后管理焦点，关闭后恢复触发元素；桌面 docked rail 不声明 `aria-modal`。

## 响应式与可访问性

- 验收视口：1440、1280、900px；文档不得出现横向溢出，长证据只在自身容器滚动。
- `≤1180px` 的 rail 是模态覆盖：打开聚焦关闭按钮，Escape 可关闭，关闭恢复 `#rail-toggle`。
- `≤900px` 的侧栏是模态抽屉：背景 inert，打开聚焦侧栏关闭按钮，关闭恢复菜单按钮。
- 隐藏导航必须同步 `aria-hidden` 与 `inert`，不能只靠 `transform` 移到屏幕外。
- 所有交互元素使用 `:focus-visible`；状态色始终配合文字。
- 支持 `prefers-reduced-motion` 与应用内减少动效开关；不使用弹跳、视差或循环装饰。
- 长列表沿用既有增量渲染与 DOM 补丁机制，不以全量重绘换取视觉效果。

## 文案语气

- 直接说任务、证据、审批、阻塞和下一步；不使用“魔法、智能涌现、一键封神”。
- 结论先行，证据随后；数字保留单位、期间和来源。
- 失败必须具体；请求已发送与服务端已完成是两种不同事实。
- 不用感叹号，不用 emoji 代替状态。

## 实现验收

1. 新颜色或尺寸先登记在 `app.css`，组件只消费 token。
2. 新呈现规则写入 `codex.css`，不新增框架、外部字体或运行时依赖。
3. 至少复核：首页、成功线程、失败线程、审批、事件 rail、治理对话／团队／工作台、
   审计库、设置、模型菜单、命令面板。
4. 每轮改动后运行 Node、Playwright、文档检查；Python 基线失败必须单独如实报告。
5. 改后截图保存到 `docs/showcase/redesign-after`，不得覆盖改前证据。
