# 记忆四层设计

> 状态:**v1 设计定稿(2026-11-02),按层逐个落地**。
> 本文回答三个问题:每层拥有什么、层间怎么流动、每一层现在缺什么。
> 上下文问题清单(有损压缩/注入隔离/状态视图/折叠/复杂度)的对策全部
> 归属到层,不再散落。

## 〇、一条总原则

**四层的区别是"寿命 × 信任 × 可变性",不是"大小"。**

| 层 | 寿命 | 持久化 | 谁可写 | 可信级别 | 可变性 |
| --- | --- | --- | --- | --- | --- |
| L1 工作记忆 | 一轮(派生物) | 不持久——链上有其全量来源 | 派生,模型**不可写** | 混合:不可信内容隔离后进入 | 每轮重建,可随时丢弃 |
| L2 会话状态 | 一次会话 | 事件链(哈希,防篡改) | 宿主(经门控);模型提议 | 宿主写入可信;模型输出是输入 | 只能经事件迁移 |
| L3 长期记忆 | 跨会话 | SQLite(cases/facts/artifacts)+ 审计包 | 会话收尾时的投影 | 已验证的结论才入册 | 追加 + 墓碑,不物理删除 |
| L4 知识库 | 永久 | git(JSON/MD) | 人评审 + CI | 评审过的、有样本锚定的 | 版本化,只增不删(规则废弃打标记) |

依赖方向:**L1 ⇄ L2 → L3 → L4 的反馈闭环,逐层信任递增、寿命递增、可变性递减。**
模型只能影响 L1(它的上下文)和 L2(它的提议);L3 只收验证过的结论;
L4 只收带样本锚定的人审变更。**注入攻击的终点是 L1 的隔离墙——不可信
内容永不落入 L2 以下任何一层。**

## 一、L1 工作记忆(每轮的模型视野)

**拥有**:压缩观测(带预算与折叠)、工具目录、计划剩余、域状态视图、
operator 消息、拒绝提议回显、不可信内容隔离包装。

**现状**:`memory/context.py::WorkingMemory` 完整实现;审计域三个插头
已落地(`flowaudit/memory.py`:evidence_summarize / quarantine /
make_audit_state_fn)。

**审计域特有约束**:
- 每个审计工具必须声明 summarizer(决策级:信号行按严重度排序、指针带
  path/line、原文进隔离包)——没有 summarizer 的审计工具不允许上注册表;
- 不可信内容(target 文件、目标运行时输出)进入 L1 必带
  `UNTRUSTED CONTENT · source=…` 包装——这是 memory 层机制,不是提示词约定;
- 折叠以指针行替代原文(store 层全量 + recall 通路),但**发现相关的
  观测永不折叠**(P1,随会话落地)。

**欠账**:折叠无重要性信号(P1-1);每轮全量重 summarize 的 O(n²)
(P1-2,缓存已折叠行的 summary 即可);RAM 全量 result(P1-3,留
summary+hash,全量归链)。

## 二、L2 会话状态(这本"改不了的账"的会话部分)

**拥有**:任务状态机、计划与 todos、预算账本、审批状态、**发现账本与
候选账本(审计域的两本账)**、覆盖面集合、模型调用的成本台账。

**现状**:运行时侧完整(task/plan/budget/approval 全在事件链上,恢复
与 CAS 已验证)。**审计侧的会话状态 API 是当前最大缺口**——发现账本
目前只是 bundle 导出物,还不是链上的会话状态。Sprint 3 第一件事:

- `flowaudit/session.py`:审计会话 = 一个 flowagent Task,审计工具注册表
  (probe/scan/read_slice/evidence-record),Analyst = deepseek provider;
- 两本账的事件化:`candidate_proposed` / `candidate_pruned` /
  `finding_promoted`(唯一晋升门 = PoC 重放收据)/ `finding_dismissed`
  (带原因)——每次迁移记录执行者(analyst/triage/host/operator);
- 状态视图:L1 的 `make_audit_state_fn` 直接投影这两本账(插头已就位)。

**纪律**:operator 在会话里的一切输入以 `actor=operator` 入链,可否决、
可停止、可调预算,**不能晋升发现**。

## 三、L3 长期记忆(跨会话的检索资产)

**拥有**:`CaseIndex`(历史运行→案例,可检索)、`FactStore`(带引证的
时效事实)、`ArtifactBook`(产物账)、运行历史与审计包。

**现状**:三个组件都是"完成态 trace → 投影"模式,接口齐全
(`upsert/query/history/tombstone`)。**审计域的接入适配器是缺口**:
审计 bundle 还不是 case,审计发现还不是 fact。

**审计域特有设计**:
- **以目标为键**:`target.manifest_sha256` 是长期记忆的主键之一——同一
  目标的历次审计构成一条时间线;
- **回归记忆**:上次审计的 finding 在本次"消失"→ 记 `fixed`;
  再次出现 → `regressed`(修复被回退是最危险的信号之一);
- **投影纪律**:进 L3 的每条发现必须带 poc-evidence 引用——L3 不收
  "模型说的",只收"重放过的"。

**落地件(Sprint 3 第二件事)**:`flowaudit/recall.py`——
`bundle → CaseIndex/FactStore 投影适配器` + `prior_findings(target_hash)`
查询(会话启动时注入 L1,让模型知道"这个靶子上次查出过什么")。

## 四、L4 知识库(版本化的判断依据)

**拥有**:AGI 分类法、规则库(JSON,版本化,只增不删)、探针库(版本化
代码,自带测试)、fixtures ground truth(dev/盲测集)、严重度锚点、
CWE 映射、威胁模型与方法论文档。

**现状**:以文件形态存在(`audit-rules/`、`fixtures/`、`docs/`)且被
CI 约束(零依赖断言、盲测隔离断言、schema 校验)。**缺口是"运行时
装载接口"的正式化**:规则引擎已读 index.json;严重度锚点、探针注册表、
目标类型 playbook 尚未结构化。

**纪律**:L4 的每个判断依据必须锚定至少一个真实样本(分类法原则);
L4 的变更进 git 评审,审计包按次钉住 ruleset_version——**历史结论必须
能追溯到当时的知识状态**。

## 五、层间流动(谁把什么交给谁)

```
L4 知识库 ──规则+探针+分类法(版本钉住)──→ L2 会话状态(启动时装载)
L2 ──state_fn 投影(发现账本/候选/盲区)──→ L1 工作记忆(每轮)
L1 ──观测与判定(经门控与事件)──────────→ L2(候选晋升/排除)
L2 ──收尾投影:bundle→case/fact(只收重放过的)──→ L3 长期记忆
L3 ──prior_findings(target_hash)──────→ L2 新会话(回归记忆)
L3+L2 的历史结论 ──人评审+样本锚定──────→ L4 知识库(规则进化)
```

## 六、落地顺序(每步带验收)

| 步 | 内容 | 验收 |
| --- | --- | --- |
| 1 | L2:审计会话 + 两本账事件化(session.py) | 断点续跑后两本账从链重建一致;operator 无法晋升发现 |
| 2 | L3:bundle→case/fact 投影适配器 + prior_findings | 同一靶子二次审计,报告含回归对比(含 regressed 检测) |
| 3 | L4:探针注册表 + 严重度锚点结构化 | 规则引用的探针全部来自注册表且有测试 |
| 4 | L1 P1:折叠重要性信号 + summary 缓存 | 长会话(≥50 轮)下关键发现仍在 inline 区;构建耗时不再随轮次平方增长 |

## 七、与既有决策的一致性

- 边界守卫(flowagent 不 import flowaudit)不受影响:L1 插头与 L2 会话
  都在 flowaudit,内核扩展点原样复用;
- SFT 字节冻结:审计会话使用自己的 prompt_profile,内核默认键的缺席
  语义不变;
- 不可信内容的终点:L1 隔离墙。L2 只存指针与判定;L3 只存已验证发现;
  L4 只有评审过的知识——**注入即使骗过 L1,也进不了账本、档案与知识**。
