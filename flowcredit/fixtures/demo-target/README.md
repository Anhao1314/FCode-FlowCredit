# MiniAgent — 审计演示靶子(缺陷是声明的,不是暗桩)

这是一个**故意写坏**的迷你 agent 应用,专门用来演示 FCode 审计器。30 秒体验:

```bash
cd flowcredit
python -m flowaudit.cli audit fixtures/demo-target
# → 2 条发现:审批记忆绕过(AGI-02)+ 明文密钥(AGI-03)
# → 每条发现附可重放的 poc-evidence 记录
```

## 声明的缺陷(别修它们——修了你自己的仓库里的同类问题)

| # | 缺陷 | 分类 | 位置 | 审计路径 |
| --- | --- | --- | --- | --- |
| 1 | 审批记忆按**工具名**键控:批准一次后,同工具任意参数免审批 | AGI-02 | `mini_agent/agent.py` 的 `_remembered` | 静态触发 → 受限重放(正反对照) |
| 2 | 源码内**明文密钥** | AGI-03 | `mini_agent/config.py` | 静态触发 → 文件状态复验 |

两点值得注意:

- **命中这两条缺陷的规则,与审计 FCode 自己用的是同一套**——规则跨代码库泛化,场景按目标绑定(`poc/scenarios/demoagent_*`)。
- `agent.py` 里还有一处"看起来能免审批"的路径(工具不在审批清单时直接放行)——那**不是缺陷**,是设计(只读工具免审批)。审计器不应报告它:这就是"候选 ≠ 发现"的含义。

## 靶子纪律

- 缺陷是**预置且公开声明**的;密钥值 `sk-demo-…` 是假的。
- 本靶子只用于演示与测试审计器,不要把它当真实代码复用。
- 修复示范:见 `tests/test_audit_fixtures.py` 里 `make_clean_control`——它展示了两处缺陷的"正确写法"。
